# yeskill 网页生图操作

通过当前环境支持的浏览器或平台工具操作用户自己的项目。根据任务交付可核对的草稿、原图，或实际提交记录。

## 1. 定位任务和操作范围

先确认目标平台、项目或画布，以及用户要做的是准备草稿、提交生成、下载结果，还是回查历史。已指定的目标直接定位。用户说「先准备」「先给我看」时，填好页面并停在提交前。只有建情绪板授权时，保存并核对情绪板即可。

优先使用支持该任务的平台工具。用浏览器时，读取当前工具的用法，再打开已知页面。确认登录身份、项目、输入区和当前草稿。遇到登录或验证，保留现场，由用户按平台流程操作。文件上传和下载都走工具公开支持的入口。

按目标读一个平台参考：

- [Holopix](references/holopix.md)：自由画布、模板、已有结果编辑、生成详情。
- [Midjourney](references/midjourney.md)：参考类型、情绪板、任务参数和原图回查。
- [Lovart](references/lovart.md)：画布选图、参数设置、连续编辑。
- 其他网站：按下述流程观察当前页面，现场识别输入、提交、任务状态和结果入口。

## 2. 配好输入，提交前回读

说明哪张是编辑底稿、其余每张图负责什么。按用户提供的顺序上传，以页面实际缩略图核对内容和编号。多个小角色的合图可做索引，重要的脸、武器和道具单独提供清晰图。项目里的旧参考或旧词先读再改。用户要求原词提交时，保留文字原样。

选定模型后回查其余设置。提交前逐项核对实际参考图与顺序、完整提示词、模型、画质、分辨率、画幅、任务数及可见费用。分清任务数、每次返回的候选数、最后下载数。关键参数不明且会改变结果或消耗时，先保留已能完成的部分，再问缺的一项。

用本轮授权决定是否提交和提交几次。每次点击后先找到新任务或明确的失败提示。按钮仍可点、页面转圈或暂无出图时，先检查任务历史和费用状态。已经排队或运行的任务继续追踪原任务。确认失败后，仍按用户授权判断是否重试。

## 3. 找回实际输入和结果

完成后打开目标结果，优先从原任务下载原图，检查文件能打开、像素尺寸、候选位置及与用户要求的差异。下载失败时回到同一任务恢复文件。

复盘以任务详情的回显为证据。保存实际提示词、参考图及顺序、可见模型与参数、任务入口、选中结果和导出文件。提交前草稿与详情有差异时，分别记录。历史缺失项写明「未查到」；预览图标注清晰度，实际文件像素尺寸与当时选择的分辨率档位分别记录。按详情中的真实输入追溯父图。

## 4. 同类网站的通用经验

- **按任务定位控件。** 先定位正确项目、任务和面板，再找该面板内的上传、提示词与设置控件。优先用名称或角色定位；图形画布靠最新截图核对。页面改版后重新观察。
- **按当前工具的方式上传。** 支持直接给上传控件设置文件时，用该入口。若工具要监听文件选择窗口，先注册监听，再点上传，最后选文件并等缩略图出现。浏览器总览失败但已有目标链接时，尝试直接定位已知标签页。
- **先分清选中、上传、关联。** 画布选中一张图、媒体库上传成功、图片进入本轮参考区是三个状态。以最后一个状态和真实顺序判断输入。
- **按状态推进。** 草稿、上传中、可提交、已提交、排队、完成、失败分别需要不同操作。连接中断后先恢复同一项目和任务，再判断是否该重试。
- **按范围验收。** 准备任务看草稿与参数；生成任务看任务完成、原图可用、结果对照；回查任务看记录是否对应真实结果。图片偏差交给用户选择下一轮方向，按当次授权安排返工。
- **对外整理时脱敏。** 用虚构示例或授权素材，移除账号、私人链接、本机路径、登录信息及不必要的页面区域。

交付记录可用一行一个字段：任务或结果入口、编辑底稿、参考图顺序与分工、实际提交词、可见参数、原图文件、实际尺寸、结果偏差。只准备草稿时，将记录标为「待提交」，已完成任务以详情回显核对。
