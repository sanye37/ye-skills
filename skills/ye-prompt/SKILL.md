# yeskill 生图提示词技巧

让 Agent 把用户意图转成真正能指导图像模型生成或编辑的提示词。

图像生成与编辑模型每次处理的都是单次任务，只接收本次的参考图、提示词和参数设置。Agent 知道的聊天历史、项目简称和先前约定，不会自动传给它。你需要利用对话理解用户意图，再组织好本次输入，在提示词里把要做的事情讲清楚。

## 本次输入

写作前确认用户本次使用的模型，以及会实际提交哪些参考图、各图的用途。对话中已经说明且能确定的信息直接沿用；未说明或仍不确定的，先向用户询问，不重复确认已知信息。用户明确不使用参考图时，按纯文字任务处理。

区分“优化提示词”与“编辑图片”：前者是 Agent 重写文字，不代表图像模型要执行局部编辑。Midjourney（含 Niji）默认按重新抽图处理，直接描述完整目标画面；仅在用户明确使用图像编辑功能时，才采用针对输入图的修改指令。

## 写作

1. 每次先理解设计师的需求，提炼本次画面的核心理念、视觉重点和决定结果的要求，再组织提示词。用方向表达可以交给模型发挥的内容，仅在影响结果时指定具体细节。采用用户当前认可的要求，补齐必要信息，剔除废弃方案、过时指令、重复描述和无关讨论。局部更新只替换被修改的要求，其余有效要求继续保留。
2. 将内部话转成模型能直接执行的画面要求，保留适用的美术术语，逐项处理名称、标签和操作用语：
   - 项目名称、内部代号只在画面需要呈现该文字时写入，并交代文字内容与位置；其余情况省去名称，将承载的题材、主体或设计要求展开为画面描述。
   - 小众艺术家姓名、情绪板名称或内部风格标签，转成可观察的视觉特征，不假定模型认识这些名称。依据用户说明和实际看过的参考图，提炼本次适用的轮廓、比例、几何造型、线条、色块、光影或材质；参考图编号及用途按第4项对应。即使使用大众熟知的风格或作品名称，也须说明本次要采用的关键特征，不能以名称代替画面要求。
   - 流程术语、聊天指代及“重新”“再来一版”“这次改成”等操作要求，转成独立的目标画面描述；明确的图像编辑任务则写清“修改图1的……，保留……”，将依据落到本次实际提供的图片。
3. 将“更有气势”“再概括一点”等评价转成与本次目标有关的画面变化。补充描述须有用户意图或参考依据，不为凑细节擅改设计；影响结果的关键含义无法确定时，先向用户澄清，不臆测简称含义或未见图片的内容。
4. 有参考图时，按本次实际输入顺序或可辨认特征逐一对应，写清各图用于参考什么；区分待编辑图与参考图，明确修改范围和保留项。只引用模型本次会收到的图片，不能让它查阅聊天里的旧图或本机文件来补全指令。
5. 优先用正向描述交代期望的画面及关系，必要时简短保留用户明确的排除要求。检查提示词与本次实际参数设置一致、各项要求相容，合并重复内容；反复改稿时围绕当前目标重写，不逐轮追加补丁。只写能指导本次生成或编辑的内容，不带入协商过程与给用户的解释。通过省略非必要细节留出设计空间，省去“具体设计自由发挥”等不增加画面信息的套话。

## 默认字数

每条中文提示词正文默认按以下上限控制，含标点，不含空格和换行：

- 单个角色、图标、场景：250字以内。
- 复杂界面、UI界面、海报：500字以内。

上述上限同样适用于优化、改写与编辑提示词。每次重新理解整体需求并提炼重点；优化某一部分时，在原有长度内替换、压缩和重分配描述，保持其他有效要求，不因优化逐次增加总字数。用户明确要求增加内容时可增加，仍遵守适用上限；用户明确指定其他长度时，按本次要求执行。压缩时保留核心理念、视觉重点、必要关系与参考图用途，将次要细节概括为设计方向。

## 交付检查

暂时放下自己知道的聊天历史，只看将提交的参考图、提示词和参数设置：图像模型能否知道要画什么、怎样呈现，或修改哪里、保留哪里？逐句确认对象、指代和比较基准均能从本次输入中确定，操作要求已经转成独立的画面描述。补齐必要信息，删除过时要求与过程用语；核对正文符合适用字数上限，修正后再交付。

默认交付本次可直接使用的完整提示词，优化局部要求也整合进完整正文，不让用户自行替换或拼接片段；仅在用户明确只要片段时交付片段。不附写作过程。此 Skill 只负责提示词写作，生成图片须依据用户另行提出的生成请求。
