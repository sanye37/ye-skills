# yeskill 生图提示词技巧

让 Agent 把用户意图转成真正能指导图像模型生成或编辑的提示词。

图片编辑模型每次处理的都是单次任务，只接收本次的参考图、提示词和参数设置。Agent 知道的聊天历史、项目简称和先前约定，不会自动传给它。你需要利用对话理解用户意图，再组织好本次输入，在提示词里把要做的事情讲清楚。

## 写作

1. 从对话中确定这一次要得到什么画面、改什么、保留什么。采用用户当前认可的要求，补齐影响本次结果的必要信息；每次写作都剔除废弃方案、过时指令、重复描述和无关讨论。局部更新只替换被修改的要求，其余有效要求继续保留。
2. 把依赖聊天才能理解的内部简称、项目代号、流程术语和指代展开成画面描述。不能只写“按某项目风格”“保留之前的设计”。结合已有说明和实际看过的参考图，按需描述可辨认的造型、比例、构图、动作、线条、色彩、光影或材质；知名作品名称也不能替代本次要采用的关键特征，保留适用的美术术语。
3. 将“更有气势”“再概括一点”等评价转成与本次目标有关的画面变化。补充描述须有用户意图或参考依据，不为凑细节擅改设计；影响结果的关键含义无法确定时，先向用户澄清，不臆测简称含义或未见图片的内容。
4. 有参考图时，按本次实际输入顺序或可辨认特征逐一对应，写清各图用于参考什么；区分待编辑图与参考图，明确修改范围和保留项。只引用模型本次会收到的图片，不能让它查阅聊天里的旧图或本机文件来补全指令。
5. 优先用正向描述交代期望的画面及关系，必要时简短保留用户明确的排除要求。检查提示词与本次实际参数设置一致、各项要求相容，合并重复内容；反复改稿时围绕当前目标重写，不逐轮追加补丁。只写能指导本次生成或编辑的内容，不带入协商过程与给用户的解释。

## 交付检查

暂时放下自己知道的聊天历史，只看将提交的参考图、提示词和参数设置：图像模型能否知道要画什么、怎样呈现，或修改哪里、保留哪里？检查是否仍有它无法理解的简称、缺失的必要信息，或会把结果带偏的旧要求与噪音。修正后再交付。

默认直接输出可用提示词，不附写作过程。此 Skill 只负责提示词写作，生成图片须依据用户另行提出的生成请求。
